## 1) 사업 목적

콜센터 상담원은 고객의 질문을 들으면서 동시에 사내 문서를 검색해야 한다. 약관·매뉴얼·공지가 흩어져 있어 숙련도에 따라 응대 품질이 갈리고, 검색하는 동안 통화는 멈춘다.

본 사업은 **통화가 진행되는 중에 시스템이 대화를 듣고, 고객이 방금 물은 내용에 필요한 문서를 상담원 화면에 자동으로 띄운다.** 상담원은 검색창에 타이핑하지 않는다.

| | 사후 처리형 | 실시간 개입형 (본 사업) |
|---|---|---|
| 입력 | 완성된 녹음 파일 | 0.3초 단위 스트리밍 조각 |
| 질의 | 완결된 문장 | 미완성 발화 |
| 레이턴시 요구 | 없음 | 1초 이내 |
| RAG 난이도 | 낮음 | 높음 (트리거 판정 + 오류 내성) |
| 제품 범주 | 통화 분석 | Agent Assist |

## 2) 주요 사업 내용

### 코어 — 절대 사수

| 블록 | 내용 | 우선순위 |
|---|---|---|
| A | **실시간 음성 처리** — 스트리밍 STT, 화자 분리, 발화 구간 검출 | 필수 |
| **B** | **자동 문서 추천 (RAG 핵심)** — 트리거 판정, 하이브리드 검색, 리랭킹, 근거 기반 카드, 출처 표시, 근거 부족 시 "관련 문서 없음" | **사수** |
| C | **컴플라이언스 감지** — 확정적 보장 표현, 개인정보 과요구, 필수 안내 누락, 권장 대체 표현 | 필수 |
| **C-5** | **개인정보 실시간 마스킹** — 자막 표시 전 + DB 저장 전 양쪽. **3주차 코어 포함** | **사수** |
| D | **통화 후 처리** — 요약, 유형 분류, 후속조치, 지식베이스 공백 리포트 | 필수 |
| **E** | **평가 하네스** — 골든셋 자동 채점, 오류율별 성능 곡선, 레이턴시 분포, 기준선 미달 시 CI 실패 | **사수** |

이 시스템은 실시간 자막을 화면에 띄우고 전사 결과를 DB에 저장한다. **마스킹이 없으면 그 자체가 설계 결함**이므로 C-5는 부가 기능이 아니라 코어다.

### 조건부 · 여유 시

| 모듈 | 내용 | 착수 |
|---|---|---|
| **F-2** | **종결 요건 검증 게이트** — 해지·명의변경·보상 처리에서 필수 근거가 없으면 종결을 차단 | 조건부 (7주차 체크포인트) |
| F-1 · F-3 · F-4 | 고위험 유형 감지 / 반복 문의 연결 / 추가 전용 처리 이력 | 여유 시 |
| G-2 | 지역 자원 연계 검색 (공개 데이터로 정답 검증 가능) | 여유 시 |
| H · I | 악성민원 대응 / 본인확인 요건 게이트 — **택1, 코어 완료 시** | 여유 시 |

**6주차 종료 시점에 코어 기준선을 통과하지 못했다면 F·G·H·I를 착수하지 않는다.** C-5만 예외로 코어에 포함된다.

### 화면 구성

| 영역 | 내용 |
|---|---|
| 좌 | 실시간 자막 — 화자 구분, **마스킹 적용 후** 표시 |
| 중 | 추천 카드 — 제목 / 근거 요약 / 출처(문서·조항) / 유사도 |
| 우 | 컴플라이언스 경고 — 감지 문구, 발생 시각, 권장 대체 표현 |
| 모달 | F-2 종결 게이트 — 필요 근거 체크리스트와 차단 사유 |

## 3) 기대 효과

| 효과 | 내용 | 확인 방법 |
|---|---|---|
| 응대 지연 감소 | 상담원이 문서를 찾는 동안의 침묵을 시스템이 대신 메운다 | 내부 처리 p95 ≤ 1,000ms |
| 숙련도 편차 흡수 | 신입도 숙련자와 같은 근거 문서를 같은 시점에 본다 | Recall@5 / MRR |
| 컴플라이언스 리스크 감소 | 확정적 보장·개인정보 과요구를 발화 즉시 경고 | 감지 재현율 ≥ 0.90 |
| **개인정보 노출 차단** | 자막·DB에 평문이 남지 않는다 | **P1~P7 패턴 누락 0건 (절대 규칙)** |
| 근거 없는 종결 억제 | 필수 확인 항목이 비면 종결을 차단한다 | F-2 판정 정확도 (조건부) |
| 지식베이스 자가 개선 | 못 찾은 질문·놓친 위반이 쌓여 보강 우선순위가 드러난다 | D-4 공백 리포트 |
| 오류 내성 확보 | STT 오인식이 있어도 검색이 무너지지 않는다 | 오류율별 성능 곡선 |

마지막 항목이 본 사업의 대표 실험이다. 음성인식은 반드시 틀리므로("해지"→"해제", "요금제"→"요금 제"), **오류가 섞인 질의에서도 정답 문서를 찾아내는 것**이 실제 성패를 가른다.

## 4) 성공 조건

> **STT 오류 내성 실험 + 검색 품질 개선 수치.** 이 두 가지가 나오면 프로젝트는 성공이다.
> **F-2는 달성 시 추가 성과로 본다.**

조건부 항목에 성공 조건을 걸지 않는다. 폴백으로 가더라도 프로젝트가 실패로 읽히지 않도록 기준을 이렇게 고정한다.

## 참고 — 제품 범주와 선행 사례

본 사업이 다루는 것은 **Agent Assist**라는 확립된 제품 범주다. Amazon Q in Connect, Google Agent Assist, LG CNS FCC RT-Advisor, KT A'Cen 등 국내외 상용 제품이 존재한다. 위험이 아니라 근거다 — 실무에서 실제로 필요한 문제라는 뜻이며, 기능 명세와 아키텍처를 비교 검증할 대상이 있다는 뜻이다.

다만 조사 범위에서 **"근거 없이 처리를 닫는 것을 차단하는" 기능(F-2)은 확인되지 않았다.** 국내 AICC는 불완전판매 방지(하면 안 되는 말 감지)까지를 제공한다.

국내 사례에서 반복 지적되는 난점이 본 사업 설계의 출발점이다.

- 통화에 카드번호·주민번호 등 민감정보가 섞인다 → **C-5 마스킹을 코어에 포함**
- LLM이 회사에 없는 정책을 말하거나 권한 밖 보상을 약속할 수 있다 → 판정은 규칙이, 설명만 LLM이
- 한국어 통화는 존댓말·지역 억양·배경 소음·업계 약어가 섞인다 → **STT 정확도가 일정하다고 가정하지 않는다**
