## 1) 용어 정의

| 용어 | 정의 |
|---|---|
| **Agent Assist** | 상담원이 통화하는 동안 시스템이 대화를 이해해 답변·문서·다음 행동을 실시간으로 제안하는 제품 범주 |
| **RAG** | 문서를 먼저 검색한 뒤 그 근거만으로 답을 생성하는 방식. 모델의 기억이 아니라 검색된 문서가 답의 출처가 된다 |
| **트리거 판정** | 스트리밍으로 들어오는 미완성 발화 중 **언제 검색을 실행할지** 결정하는 로직 |
| **허용 창** | 발화 종료 후 이 시간 안에 발동하면 "적절"로 채점하는 구간. 현재 0~1,500ms |
| **STT** | 음성 인식. 본 사업에서는 부분 결과를 포함한 스트리밍 인식을 사용 |
| **화자 분리** (Diarization) | 오디오에서 누가 말했는지 구분하는 처리. 2채널 스테레오면 물리적으로 분리되어 불필요 |
| **VAD / 발화 구간 검출** | 침묵과 발화를 구분해 말이 끝난 시점을 판정하는 처리 |
| **BM25** | 단어 빈도 기반 전통적 검색 랭킹 함수 |
| **nori** | Elasticsearch의 한국어 형태소 분석기. 띄어쓰기 오류 흡수에 사용 |
| **자모 분해 필터** | 한글을 초·중·종성으로 분해해 색인. 유사 발음 오인식("해지"→"해제") 대응 |
| **dense_vector** | 문장 임베딩 벡터를 저장하는 ES 필드 타입 |
| **하이브리드 검색** | 형태소 검색과 벡터 검색을 함께 실행해 결과를 합치는 방식 |
| **RRF** | 서로 다른 검색 결과의 순위를 역수로 합산해 병합하는 표준 기법 |
| **리랭킹** | 1차 검색 상위 후보를 더 정밀한 모델로 재정렬하는 단계 |
| **청킹** | 긴 문서를 검색 단위로 쪼개는 작업 |
| **골든셋** | 정답이 라벨링된 평가용 시나리오 모음 |
| **Recall@5** | 상위 5개 검색 결과 안에 정답 문서가 포함된 비율 |
| **MRR** | 정답이 몇 번째에 나왔는지를 역수로 평균한 값 |
| **재현율 / 정밀도** | 재현율 = 실제 위반 중 잡아낸 비율, 정밀도 = 경고한 것 중 진짜 위반인 비율 |
| **환각** | 근거 문서에 없는 내용을 모델이 지어내는 현상. 특히 수치 환각을 별도 측정 |
| **p50 / p95 / p99** | 응답 시간 분포의 백분위 |
| **내부 처리 지연 / E2E 체감 지연** | 트리거 발동→카드 표시 / 발화 종료→카드 표시. 후자는 통제 밖 구간을 포함 |
| **CER** | 음성인식 오류율을 글자 단위로 측정한 값 |
| **기준선** | 개선 전 성능을 고정해둔 수치. 이후 변경이 이보다 나빠지면 CI가 실패한다 |
| **C-5** | 개인정보 실시간 마스킹 모듈. 자막 표시 전 + DB 저장 전 양쪽에 적용 |
| **P1~P7** | 마스킹 대상 패턴 — 주민번호/카드/계좌/휴대전화/인증번호(정규식), 인명/상세주소(NER) |
| **F-2** | 종결 요건 검증 게이트. 필수 근거가 없으면 종결을 차단한다 |
| **폴백 모드** | 생성 없이 검색 원문 스니펫만 카드에 표시하는 모드. GPU 미확보·레이턴시 초과 시 기본값 |
| **절대 규칙** | 평균이 아니라 1건이라도 뚫리면 실패로 처리하는 지표 (C-5 누락 0건, F-2 판정) |
| **순환 검증** | 팀이 만든 규칙을 팀이 만든 데이터로 검증해 결과가 자기충족적이 되는 상태 |

## 3) 민감 기능 공통 설계 원칙

C-5, F, G 및 부록 모듈에 **공통 적용**한다. 코드보다 먼저 합의한다.

### 시스템의 발언 범위

| 할 수 있는 말 | 하면 안 되는 말 |
|---|---|
| "위험 신호가 감지되었습니다" | "안전합니다" |
| "이 종결 사유는 근거 3건이 필요합니다" | "이 건은 종결해도 됩니다" |
| "이 요청 유형은 확인 항목 3건이 필요합니다" | "이 사람은 위험도 78%입니다" |

### 판정과 설명의 분리

- **판정은 규칙이 한다** — 종결 가능 여부, 요건 충족, 마스킹 대상, 기관 매칭 전부 결정론적 로직
- **LLM은 설명만 한다** — 판정 결과를 사람이 읽을 문장으로 옮기는 역할
- 숫자와 판정을 생성 모델에 맡기지 않는다

### 주장의 한계

| 쓰지 않을 표현 | 대신 쓸 표현 |
|---|---|
| "이 시스템이 있었으면 막을 수 있었다" | "근거 없는 종결을 구조적으로 어렵게 만드는 설계를 검토했다" |
| "불변 감사 로그" | "추가 전용 감사 로그 — 완전한 불변성은 애플리케이션 레벨에서 보장 불가" |
| "개인정보를 완벽히 차단합니다" | "정의된 P1~P7 패턴에 대해 누락 0건을 목표로 한다" |

### 발표·시연 주의

- 개별 사건의 실명·지역·세부 정황을 쓰지 않는다. 문제 정의는 **일반적 실패 유형**으로 서술한다
- 위기 통화를 재현하는 데모는 하지 않는다
- 실제 위기 상담 음성·기록을 수집하지 않는다. 시연·평가용 시나리오는 팀이 작성한 가상 사례만 사용한다
