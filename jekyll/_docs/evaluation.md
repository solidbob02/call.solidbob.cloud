## 1) 채점 원칙 (변경 금지)

1. **LLM을 채점자로 쓰지 않는다.** 답을 만든 모델이 자기 답을 심판하면 순환이 된다. 모든 지표를 규칙으로 계산해 재현 가능하게 한다.
2. **여러 번 실행한 값 중 최저치를 기준선으로 고정한다.**
3. **기준선 미달은 CI 실패.** 목적은 개선이 아니라 회귀 방지다.
4. **절대 규칙(C-5 누락 0건, F-2 판정 정확도)은 1건이라도 뚫리면 실패다.** 평균으로 평가하지 않는다.
5. **모든 지표는 정답 정의가 코드로 표현 가능해야 한다.** 표현할 수 없으면 지표가 아니다.
6. **측정하지 않은 수치는 기록하지 않는다.** 미측정은 `null`.

## 2) 하네스 구성 (E 블록)

| 기능 | 내용 |
|---|---|
| E-1 | 골든셋 기반 자동 채점 (규칙 기반) |
| E-2 | STT 오류율별 성능 곡선 자동 생성 (검색 + 마스킹 재현율) |
| E-3 | 레이턴시 분포 측정 — **내부 처리와 E2E를 분리해 각각 p50/p95/p99** |
| E-4 | 기준선 미달 시 CI 실패 |

하네스 **설계**는 1주차에 백엔드·AI 담당이 끝내고, **운영은 인프라 담당이 이관받는다.** 모듈을 고칠 때마다 숫자가 자동으로 나오므로 "이 방식이 더 나은 것 같다"가 측정으로 대체된다.

## 3) 기준선

목표치 표는 [3. 주요 개발 수행 지침]({{ '/docs/3-guidelines/#3-품질-관리-및-테스트' | relative_url }})에, 실측 현황은 [진행 상황]({{ '/progress/' | relative_url }})에 있다. 두 곳 모두 `jekyll/_data/metrics.yml` 하나를 참조한다.

**베이스라인은 두 단계다.** 2주차 잠정값(골든셋 50개)은 방향 확인용이며 CI에 고정하지 않는다. CI에 박히는 기준선은 3주차 150개 셋 완성 후 재측정값이다.

## 4) 측정할 수 없는 것

검증할 수 없는 것을 검증한 것처럼 제시하지 않는다.

| 항목 | 한계 |
|---|---|
| **F-1 / G-1 탐지 성능** | 실제 고위험 통화 데이터 확보 불가. **측정 불가** |
| **C-5 마스킹** | 실제 통화의 개인정보 발화 패턴을 확보할 수 없다. **"P1~P7 패턴 목록에 대한 누락 0건"**으로 범위를 한정해 측정한다 |
| **F-2 판정 정확도** | **규정·골든셋·게이트를 모두 팀이 작성했다.** 100%는 "규칙 엔진이 명세대로 동작한다"는 의미이며, "실무 규정을 올바르게 해석한다"는 뜻이 아니다 |
| H-1 (부록 모듈) | AI Hub 감정 태깅은 폭언 라벨과 다르다. 화난 고객이 모두 폭언을 하지 않고, 차분한 어조의 성희롱도 있다 |
| 오류 내성 실험 | 통제된 합성 오류 기반. 실제 STT 오류 분포와 완전히 같지 않다 |

> **측정 불가능한 절대 규칙은 범위가 한정된 절대 규칙보다 나쁘다.** C-5의 목표를 패턴 목록으로 한정하는 것은 완화가 아니라 검증 가능하게 만드는 조치다.

### F-2의 순환 검증 — 완화 조치

한계를 적는 것만으로는 부족하므로 작업 배분으로 완화한다.

1. 규정 문서는 **실제 통신사 약관의 조 번호 체계·문장 형식·용어**를 따라 작성한다
2. **규정 작성자와 요건 스키마 구현자를 분리한다**
3. **골든셋의 F-2 케이스는 규정 작성자가 아닌 사람이 만든다**
4. 위 세 가지를 지켰다는 사실을 문서에 적는다

3인이므로 규정 작성·스키마 구현·골든셋 라벨링을 한 사람씩 나눠 맡을 수 있다.

## 5) 수치 기록 규칙

측정값은 `jekyll/_data/metrics.yml` 한 곳에만 쓴다. 한 건에는 반드시 다음이 붙는다.

```yaml
value: 0.66
measured_at: 2026-09-20
commit: a1b2c3d
command: "python eval/run.py --error-rate 0.10"
n: 150
```

넷 중 하나라도 못 채우면 그 숫자는 아직 기록할 준비가 되지 않은 것이다.
