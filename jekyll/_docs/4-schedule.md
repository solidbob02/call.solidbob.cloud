## 2) 조직 구성 및 역할 분담

| 트랙 | 담당 범위 | 담당자 |
|---|---|---|
| ① 음성 파이프라인 | 오디오 스트리밍, STT 연동, 화자 분리, 발화 구간 검출 | 미정 |
| ② 검색 | ES 인덱스 설계, nori·자모 필터, 하이브리드 검색, 리랭킹 | 미정 |
| ③ 실시간 코어 | 트리거 판정, 생성, 레이턴시 최적화, 캐싱 | 미정 |
| ④ 분류·후처리 | 컴플라이언스 분류기, 요약, 유형 분류 | 미정 |
| ⑤ 프론트·인프라 | React 대시보드, WebSocket, Docker | 미정 |
| 리드 | 인터페이스 계약, 평가 하네스, CI, 품질 기준 | 미정 |

> **미결**: 실제 인원 구성이 확정되지 않았다. 5인 분업을 전제로 한 계획이므로, 인원이 이보다 적으면 A(음성)와 C(컴플라이언스)를 축소하고 B(검색)·E(평가)에 집중하는 재계획이 필요하다. → [미결 항목]({{ '/open-items/' | relative_url }})

### 협업 방식

- 1주차 인터페이스 계약 확정 후 트랙별 병렬 진행
- 품질은 평가 하네스가 자동 검증한다. 리드는 대신 구현하지 않고 리뷰한다
- 모든 작업 세션은 개발 로그 1건을 남긴다 (형식은 `CLAUDE.md`)

## 3) 위험 관리 방안

| 리스크 | 영향 | 대응 |
|---|---|---|
| **AI Hub 승인 지연** | 평가 데이터 확보 실패 | 1주차 즉시 신청. TTS 합성을 2순위 대비책으로 병행 준비 |
| Google STT 한국어 성능 미달 | 파이프라인 전체 품질 저하 | 공개 벤치마크로 사전 확인. **오류 내성 설계 자체가 주제이므로 오류가 많아도 실험은 성립** |
| STT API 비용 초과 | 예산 소진 | 반복 실험은 녹음 파일 배치 모드. 실시간 데모만 스트리밍 |
| 레이턴시 목표 미달 | 데모 설득력 저하 | 목표를 못 맞춰도 **측정하고 원인을 분해한 기록**이 남으면 성과로 인정된다 |
| 범위 과다 | 미완성 | C(컴플라이언스)·D(후처리)를 후순위로. B·E 는 사수 |
| 인원 편차 | 리드에게 작업 집중 | 평가 하네스로 품질 자동 검증. 대신 짜주지 않고 리뷰로 올린다 |
| 약관 저작권 | 공개 시 문제 소지 | 원문 전재 대신 요약·해석 + 출처 표시. 발표 자료에도 인용 최소화 |
| 개인정보 | 실데이터 사용 시 | AI Hub 데이터는 가상 시나리오 기반으로 저작권·개인정보가 해결되어 있다. 자체 녹음은 하지 않는다 |
| 지식베이스 라벨링 난이도 | 골든셋 구축 실패 | 1주차에 10건 시범 작성으로 검증. 막히면 도메인을 바꾼다 |
