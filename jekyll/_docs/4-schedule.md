### 1주차 최우선

1. **AI Hub 데이터 신청** — 휴대폰 본인인증과 승인 대기. 첫날 신청하지 않으면 데모·파이프라인 검증이 밀린다. 다만 5주차 핵심 실험은 텍스트 레벨 오류 주입이므로 **승인과 무관하게 진행 가능**하다.
2. **V1~V4 전제 확인** — 확인하지 않으면 후속 설계가 흔들린다.

| # | 확인 대상 | 미확인 시 영향 |
|---|---|---|
| V1 | AI Hub 데이터의 채널 구성 (2채널 / 모노) | 화자 분리 난이도 → C-1~C-3, C-5 전체 |
| V2 | GPU 가용 여부 | 생성 모델 크기, 레이턴시 예산, **폴백 모드 전환 판단** |
| V3 | Google STT 한국어 숫자 출력 형태 | C-5 정규화 단계 설계 |
| V4 | STT 스트리밍 부분 결과 지연 | E2E 지표 기준값 |

### 7주차 중반 체크포인트

> 코어 기준선 통과 + 태스크 궤도 정상 → **F-2 구현 진행**
> 둘 중 하나라도 미달 → **F-2를 설계 문서로 전환** (시퀀스 다이어그램 + 요건 스키마 산출)

### 성공 조건

> **STT 오류 내성 실험 + 검색 품질 개선 수치.** 이 두 가지가 나오면 성공이다. **F-2는 추가 성과.**

**범위 관리 규칙**: 6주차 종료 시점에 코어 기준선을 통과하지 못했다면 F·G·H·I를 착수하지 않는다. **C-5만 예외로 코어에 포함되므로 3주차에 반드시 들어간다.**
8주차 후반 3일은 발표·문서 전용으로 고정하고 개발 태스크를 넣지 않는다.

## 2) 조직 구성 및 역할 분담

**3인 팀**

| 담당 | 인원 | 범위 |
|---|---|---|
| **AWS·인프라** | 정성윤 | Node.js WebSocket 게이트웨이, Google STT 연동, 화자 분리, **C-5 P1~P5 마스킹**, MySQL 스키마, Docker·배포, 레이턴시 측정 인프라, **CI 운영** |
| **백엔드·AI** | 류준 | ES 인덱스 설계·하이브리드 검색·리랭킹, 트리거 판정, 생성 모듈, 컴플라이언스 분류기, **C-5 P6~P7 NER**, **F-2 게이트**, 평가 하네스 설계 |
| **앱·프론트엔드** | 장민석 | React 대시보드(자막·카드·경고·종결 모달), WebSocket 클라이언트, 데모 시나리오, 결과 시각화 |
| 공동 | 3인 | 골든셋 작성·라벨링, 발표 자료 |

### 부하 경고 — 반드시 읽을 것

**류준이 백엔드와 AI를 동시에 맡고 있어 구조적으로 과부하다.** 4·5주차 핵심 실험과 F-2가 모두 한 사람에게 걸려 있다. 완화 조치를 문서에 고정한다.

| 조치 | 내용 |
|---|---|
| C-5 정규식(P1~P5)을 정성윤에게 | 전사 직후 처리 지점이라 STT 파이프라인 담당이 자연스럽다 |
| **단, P6~P7(NER)은 류준** | 보완지시서 4 — 정규식이 아니라 모델 로드·튜닝이다. 5주차 마스킹 재현율 곡선도 오류 주입 스크립트와 맞물리므로 AI 담당 |
| **CI 운영을 정성윤에게 이관** | 류준은 1주차에 하네스 **설계**만, 이후 운영·유지는 정성윤 |
| 골든셋은 3인 공동 | 라벨링은 도메인 이해만 있으면 되므로 분산 가능 |
| 장민석이 시각화 담당 | matplotlib 성능 곡선·레이턴시 분포를 프론트 담당이 가져간다 |
| **F-2는 조건부** | 류준의 코어 작업이 지연되면 설계 문서로 전환 (7주차 체크포인트) |

부하 완화 조치는 **3인 합의 사항**이다. 합의 여부를 1주차에 확인한다.

### 협업 방식

- 1주차 인터페이스 계약 확정 후 병렬 진행
- 품질은 평가 하네스가 자동 검증한다. 대신 구현하지 않고 리뷰한다
- 모든 작업 세션은 개발 로그 1건을 남긴다 (형식은 `CLAUDE.md`)
- F-2는 **규정 작성 / 스키마 구현 / 골든셋 라벨링을 서로 다른 사람이** 맡는다 → [3. 주요 개발 수행 지침]({{ '/docs/3-guidelines/#1-일반-사항' | relative_url }})

## 3) 위험 관리 방안

| 리스크 | 영향 | 대응 |
|---|---|---|
| **AI Hub 승인 지연** | 데모·파이프라인 검증 지연 | 1주차 즉시 신청. **핵심 실험은 텍스트 레벨 오류 주입이라 승인과 무관** — 영향 범위가 좁다 |
| **화자 분리 정확도 미달** | C-1~C-3, C-5 전체의 성능 상한선이 됨 | V1으로 1주차 확인. 모노일 경우 시연은 물리 2채널로 우회하고 한계 명시 |
| **류준 부하 집중** | 코어와 F-2가 한 사람에게 걸림 | 위 완화 조치 적용. F-2 조건부 착수 |
| **GPU 미확보** | 생성 모델 크기 제약, 첫 토큰 500ms 미달 | V2로 1주차 확인. **폴백 모드(검색 스니펫만 표시)로 전환 — 코어 가치는 유지된다** |
| **F-2 규정을 팀이 작성** | 판정 정확도 100%가 자기충족적 수치가 됨 | 실제 약관 체계에 맞춰 작성. **규정 작성자 / 스키마 구현자 / 골든셋 작성자 분리.** 한계를 문서에 명시 |
| Google STT 한국어 성능 미달 | 파이프라인 품질 저하 | 공개 벤치마크 사전 확인. **오류 내성 설계 자체가 주제이므로 오류가 많아도 실험은 성립** |
| STT API 비용 초과 | 예산 소진 | 반복 실험은 배치 모드. 실시간 데모만 스트리밍 |
| 레이턴시 목표 미달 | 데모 설득력 저하 | 목표 미달해도 **측정하고 원인을 분해한 기록**이 있으면 성과 |
| 범위 과다 | 미완성 | F·G·H·I는 조건부. B(검색)·E(평가)·C-5를 절대 사수 |
| **개인정보 노출** | 자막·DB에 평문 저장 | **C-5를 3주차 코어로 포함.** P1~P7 누락 0건 |
| 약관 저작권 | 공개 시 문제 소지 | 원문 전재 대신 요약·해석 + 출처 표시 |
| 민감 도메인 표현 | 과장·부적절 서술 | 부록 A 원칙 준수. 개별 사건 실명·세부 인용 금지 |
| 지식베이스 라벨링 난이도 | 골든셋 구축 실패 | 1주차에 10개 시범 작성으로 검증. 막히면 지식베이스 구성을 바꾼다 |
