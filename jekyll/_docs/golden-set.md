> 현재 상태: **미착수**. 문서 수집·청킹·ID 부여가 끝나야 라벨링을 시작할 수 있다.

## 일정 — 순환 의존을 끊는다

정답 라벨이 "이 시점에 표시되어야 할 문서 ID"이므로, **문서 수집 → 청킹 → ID 부여가 선행되어야 한다.** 문서 수집과 골든셋 대량 작성을 같은 주에 병렬 배치하는 것은 물리적으로 불가능하다.

| 주차 | 규모 | 용도 |
|---|---|---|
| 1주차 | **10개** | 문서 수집 + 청킹 + ID 부여 후. 라벨링 가능성 검증 |
| 2주차 | **50개** | **잠정 베이스라인** 측정 — 방향 확인용, CI에 고정하지 않는다 |
| 3주차 | **150개** | **공식 기준선** 확정 — CI에 박히는 값 |

1주차 10개에서 막히면 지식베이스 구성을 바꿔야 한다.

## 시나리오 한 건의 구성

```
- 고객 발화 스크립트
- 발화 종료 시각            ← 트리거 채점용. 없으면 적절 발동률을 계산할 수 없다
- 이 시점에 표시되어야 할 문서 ID   ← 정답 라벨
- 표시되면 안 되는 문서 ID          ← 오답 후보 (혼동 유발용)
- 컴플라이언스 위반 삽입 여부
- 개인정보 패턴 삽입 여부 (P1~P7 중)  ← C-5 채점용
- (F-2 케이스) 처리 유형 + 근거 필드 충족 상태 + 기대 판정
```

> **F-2 케이스는 규정 작성자가 아닌 사람이 만든다.** 같은 사람이 만들면 규정의 빈틈이 그대로 통과되어 판정 정확도가 자기충족적 수치가 된다.

## 음성 확보

| 순위 | 방법 | 비고 |
|---|---|---|
| 1 | AI Hub 데이터에서 유사 시나리오 매칭 | 승인 필요, 1주차 즉시 신청 |
| 2 | TTS 합성 | 승인 지연 대비책 |

자체 통화 녹음은 하지 않는다.

| 데이터셋 | 규모 | 특징 |
|---|---|---|
| AI Hub 상담 음성 | 3,000시간 | 교육·금융·통신판매, 가상 시나리오, 저작권 해결 |
| AI Hub 고객 응대 음성 | 3,300시간 | 감정·의도 태깅 및 요약문 포함 |
| AI Hub 저음질 전화망 음성 | — | 실제 상담 환경 잡음 |
| 서울 열린데이터광장 행정 민원상담 음성 | 56개 유형 | 8kHz, 연령·지역·성별 조합 |

**V1 확인 필요**: 위 데이터의 채널 구성(2채널 스테레오 / 모노)에 따라 화자 분리 난이도가 갈린다.

## STT 오류 주입

| 유형 | 예 |
|---|---|
| 자모 치환 (유사 발음) | 해지 → 해제 |
| 띄어쓰기 변형 | 요금제 → 요금 제 |
| 동음이의 치환 | 위약금 → 위약 금 |

오류율 0 / 5 / 10 / 15 / 20 % 구간으로 **검색 성능 곡선과 C-5 마스킹 재현율 곡선**을 함께 만든다.

이 실험은 실제 데이터 부족을 대체하는 합성이 아니라 **구간별 비교를 위해 오류율을 통제한 설계**다. 실제 통화로는 5%/10%/15% 곡선을 그릴 수 없다.

## 지식베이스 — 하나로 유지

**통신사 요금제 약관 + 응대 매뉴얼 + 내부 처리 규정**을 한 ES 인덱스에 적재한다. F-2가 참조하는 종결 요건도 이 안에 있다.

- 응대 매뉴얼과 내부 처리 규정은 팀이 직접 작성한다(가상 사업자 기준). 실제 약관의 조 번호 체계·문장 형식·용어를 따른다
- 약관 원문은 검색 인덱스 내부 저장까지만. 화면·공개 문서에는 요약·해석 + 출처만 싣는다
