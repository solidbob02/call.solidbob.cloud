⚠ **2주차의 다른 작업이 전부 이 결정에 걸려 있다.** 통화가 금융보험·다산콜센터·쇼핑·
질병관리본부 중 어느 도메인인지 정해지지 않으면 어느 인덱스를 검색할지 모른다.

## 선택지

| | 방법 | 비용 | 위험 |
|---|---|---|---|
| **A** | 상담원이 통화 시작 시 **수동 선택** | 구현 1시간. 화면에 드롭다운 하나 | 데모에서 클릭 한 번이 늘어남 |
| **B** | **첫 발화로 자동 분류** | 분류기 하나 추가 학습·평가 | 5주차 오류 내성 실험 대상이 하나 늘어난다. 오분류 시 검색이 통째로 빗나감 |

## 판단 재료

- 실제 콜센터도 대개 **인입 번호·메뉴로 도메인이 이미 갈려 있다.** A안이 현실과 더 가깝다
- 코어(B 검색·E 평가)를 사수해야 하는 8주 프로젝트다. 기획서에 없는 분류기를 하나 더
  만들 여유가 있는지 따져야 한다
- B안을 택하면 **분류 정확도도 측정 대상**이 된다. 측정하지 않은 수치는 쓸 수 없으므로
  골든셋에 도메인 라벨과 오분류 케이스가 추가로 필요하다

## 완료 조건

반영 여부 확정([7.3절](/docs/07/)).

## 2026-08-26 — 결정: B안(자동 분류)

위 "판단 재료"는 A안(수동 선택)에 무게를 뒀으나, **팀은 B안을 택했다.** 상담원이 매번
도메인을 고르지 않는다. 근거·되돌리는 법: `_project/decisions/007-도메인-라우팅-자동분류-확정.md`.

설계는 2단이다 — 초반 발화를 KcELECTRA 계열 분류기(**B-0**)로 4클래스 분류하고,
신뢰도가 낮으면 4개 인덱스를 전부 하이브리드 검색하는 폴백으로 판정한다. 새 도구는
도입하지 않는다.

A안을 밀던 "분류 정확도도 측정 대상이 된다"는 지적은 그대로 유효해서, 평가 하네스에
먼저 배선했다 — `fastapi/apps/evaluation/metrics/domain_routing.py`(정확도 + 오분류 행렬,
규칙 기반), 골든셋 `domain` 필드를 정답 라벨로 재사용, 목표 정확도 ≥0.95([6.1절](/docs/06/)).
분류기가 없는 동안은 "측정 불가 — 모듈 미구현"으로 보고한다.

**아직 `done` 이 아닌 이유**: 완료 조건 중 **인터페이스 계약의 도메인 필드 반영 여부**가
미결이다. 메시지에 `domain` 을 명시적으로 넣을지, `call_id` 로 서버가 `call.domain` 을
조회할지 아직 안 정했다([7.3절](/docs/07/) 주석, [3.2절](/docs/03/)).

실제 분류기 구현·학습은 이 티켓이 아니라 [w1-domain-routing](/backlog/w1-domain-routing/)
에서 이어진다 — 골든셋 50건(2주차) 확보가 전제다.
