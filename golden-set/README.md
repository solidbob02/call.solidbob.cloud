# 골든셋 — v1 (10개)

[데이터 확보 계획 5.3절](/docs/05/)의 1주차 목표(10개)를 채운 초안이다.
`knowledge-base/`의 실제 문서 ID를 그대로 참조하므로, 지식베이스 문서가 바뀌면 이
골든셋도 같이 갱신해야 한다.

## 파일

- `v1-10.json` — 항목 10개. 스키마는 아래 참고.

## 스키마 (5.3절 "골든셋 스펙에 포함할 항목" 그대로)

| 필드 | 설명 |
|---|---|
| `customer_utterance` / `agent_utterance` | 고객 또는 상담원 발화 스크립트 |
| `utterance_end_ms` | 발화 종료 시각 — [4.1절](/docs/04/) 트리거 채점(0~800ms 허용창)용 |
| `expected_doc_ids` | 이 시점에 표시되어야 할 정답 문서 ID |
| `distractor_doc_ids` | 표시되면 안 되는 오답 후보 문서 ID |
| `compliance_violation` | C-1~C-4 위반 삽입 여부와 유형 |
| `pii_patterns` | P1~P7 개인정보 패턴 삽입 여부 (C-5 채점용) |
| `f2_case` | 처리 유형 + 근거 필드 충족 상태 + 기대 판정 (F-2 케이스만) |

## 모듈별 분포 (10개)

| 모듈 | 개수 | 내용 |
|---|---|---|
| B (검색) | 3 | 프로모션 할인·요금제 변경·위약금 문의 — 정답/오답 문서 구분 |
| C-1·C-2 (컴플라이언스) | 2 | 확정적 보장 표현, 불필요한 개인정보 요구 |
| C-5 (마스킹) | 2 | 구분자 있는 표준 형태, **구분자 없는 붕괴 형태**(주 실패 모드) |
| F-2 (종결 게이트) | 3 | 해지 승인/차단, 명의변경 차단 — [POLICY](/docs/02/) 필드 구조 검증 |
