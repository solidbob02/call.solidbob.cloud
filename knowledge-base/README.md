# 지식베이스 — 도메인 4종 (2026-08-26 재구성)

[데이터 확보 계획 5.1절](/docs/05/)에 따라 팀이 직접 작성하는 문서다. 원래는 가상 통신사
"한별텔레콤" 단일 도메인 기준이었으나, **실제로 확보한 데이터가 통신이 아닌 4개
도메인(금융보험·다산콜센터·쇼핑·질병관리본부)에만 있다는 사실을 반영해 도메인별로
재구성했다.** 근거·되돌리는 법: `_project/decisions/004-데모-도메인-4종-확정.md`.

각 도메인 문서는 **약관 원문을 전재하지 않고, 가상 사업자/기관 기준으로 처음부터
작성**한다 — 저작권 문제가 없고, 프로젝트가 원하는 규칙(C-1~C-4 위반 유형, F-2 필수
확인 항목)을 정확히 반영하도록 설계할 수 있다. 다만 카테고리·의도 체계는 AI Hub
「민원(콜센터) 질의-응답」데이터셋(`data/raw/aihub-minwon-qa/`)의 실측 라벨을 따른다.

## 도메인별 문서 3종

각 도메인 폴더 아래 공통 구조를 둔다.

| 하위 폴더 | 문서 | 역할 |
|---|---|---|
| `terms/` | 이용약관/안내지침 | B(검색) 대상. 화면에 "출처: 이용약관 N.N조"로 인용됨 |
| `manual/` | 응대 매뉴얼 | B(검색) 대상. F-2 근거로도 쓰임(해당 도메인만) |
| `policy/` | 내부 처리 규정 | **F-2 게이트가 직접 참조**하는 처리유형별 필수 확인 항목 정의 (F-2 미적용 도메인은 미적용 사유와 대체 검증 수단을 명시) |

네 도메인 × 세 문서 = 12개 문서가 **도메인별로 별도 Elasticsearch 인덱스(또는 같은
인덱스의 `domain` 필드)**에 적재된다. 상담 중에는 통화가 어느 도메인인지 먼저 라우팅한
뒤 해당 도메인 인덱스에서만 검색한다([아키텍처](/docs/03/) 갱신 필요 — 후속 티켓).

## ID 체계

도메인 코드 접두어 + 기존 체계를 그대로 쓴다. `<!-- id: ... -->` 주석으로 문서 ID를
붙였다.

| 도메인 | 접두어 | 예시 |
|---|---|---|
| 금융보험 | `FIN-` | `FIN-TERM-3.2`, `FIN-MANUAL-3.1`, `FIN-POLICY-CLOSE-1` |
| 다산콜센터 | `DASAN-` | `DASAN-TERM-5.1`, `DASAN-MANUAL-4.1` |
| 쇼핑 | `SHOP-` | `SHOP-TERM-4.3`, `SHOP-POLICY-RETURN-1` |
| 질병관리본부 | `HLT-` | `HLT-TERM-2.1`, `HLT-MANUAL-1.1` |
