# 세션 마무리 (CLAUDE.md §0.5)

작업이 있었던 세션은 이 절차로 끝낸다. **커밋·푸시·PR 은 세션의 끝이 아니다.**

## 왜 이 스킬이 있나

2026-08-25~26 이틀간 PM 세션의 진행 기록이 **0건**이었다. 같은 기간 다른 팀원은 5건 남겼다.
내용을 빠뜨린 게 아니라 **PR 본문에만 쓰고 진행 기록으로 옮기지 않았다.**
PR 은 머지되면 닫히고, 팀이 보는 것은 `/progress/` 페이지다.

지금까지 지켜진 규칙(자격증명 금지·한글 파일명 금지)은 전부 어기면 즉시 드러나거나 CI 가 잡는 것이었다.
진행 기록만 **어겨도 아무 일이 없어서** 뚫렸다.

## 순서

### 1. 무엇이 바뀌었는지 확인

```bash
git status --short
git log --oneline --since='today 00:00'
python3 scripts/check_session_end.py      # 세 검사를 한 번에 (경고만)
```

### 2. 진행 기록을 먼저 쓴다

**항목 1건 = 파일 1개.** `jekyll/_logs/` 에 새 파일을 만든다. 남의 파일은 건드리지 않는다.

```bash
ls jekyll/_logs/$(date +%F)-*      # 오늘 내 seq 가 몇 번까지 갔는지 확인
```

```markdown
<!-- jekyll/_logs/2026-08-27-01-ryujun.md -->
---
date: 2026-08-27
author: "류준"          # 정성윤 | 류준 | 장민석 | 조서희
person: ryujun          # seongyun | ryujun | minseok | seohee
seq: 1                  # 같은 날 안에서의 순서. **자기 것만** 센다
---

- **무엇을 했는지** — 왜 그렇게 했는지, 무엇을 확인했는지
- 남은 것: 다음 세션이 이어받을 것
```

- 파일명은 `YYYY-MM-DD-{seq}-{person}.md`. **`seq` 는 두 자리**로 쓴다 —
  정렬이 파일 경로 기준이라 `9` 로 쓰면 `10` 보다 뒤로 간다
- **`seq` 는 자기 것만 센다.** 남과 겹쳐도 된다 — 파일명에 작성자가 들어가 서로 다른
  파일이 되므로 브랜치를 합칠 때 충돌이 나지 않는다. 예전의 팀 공유 번호(`(44)`)가
  아니다. 그 공유 번호가 실제로 2026-08-26 에 두 번 충돌했다(`_project/decisions/016`)
- **진행 기록을 먼저 쓰고 PR 본문으로 옮긴다.** 반대 방향은 유실된다
- 한 번 쓴 파일은 고치지 않는다. 틀린 것은 새 파일로 정정한다
- 안 된 실험·미달 지표·틀린 가설도 그대로 남긴다 (절대 원칙 8)
- 측정하지 않은 수치를 적지 않는다 (절대 원칙 2)
- 뒤늦게 남기는 기록은 지난 날짜에 끼워 넣지 않는다. **현재 시점에 "백필"로 명시**한다

### 3. 칸반 티켓을 실제와 맞춘다

```bash
ls jekyll/_backlogs/
```

- **시작한 일에는 티켓이 있어야 한다.** 없으면 지금 만든다 (끝난 뒤 몰아서 만들지 않는다)
- 손댄 티켓의 `status` 를 옮긴다 — `todo` → `in-progress` → `done`
- `status` 값은 이 셋뿐이다. 다른 값을 쓰면 `where` 필터에 안 걸려 **카드가 조용히 사라진다**
- `assignee` 는 실제로 손댄 사람. 문자열이 곧 그룹 이름이라 오타 하나면 없는 사람이 보드에 생긴다
- 파일명은 `w{주차}-{영문-슬러그}.md`. 한글 파일명은 URL 이 깨진다

### 4. 중복 티켓을 확인한다

`check_session_end.py` 가 슬러그가 겹치는 쌍을 경고한다. 실제로 이런 일이 있었다:

```
w1-db-schema  ↔  w2-db-schema-domain     내가 2주차 티켓을 만드는 동안 팀원이 1주차 티켓을 만듦
w1-dashboard-scaffold ↔ w2-dashboard-scaffold
```

**정리 기준**

- 실제 작업이 일어난 티켓을 남긴다. 나머지는 지우거나 `done` 으로 옮기되,
  **어느 티켓에서 끝났는지를 본문에 적는다** — 안 그러면 보드에서 완료가 두 번 세어진다
- 아직 `todo` 인 티켓은 보존할 수행 기록이 없으므로 합치고 지워도 된다
- 이미 `in-progress`·`done` 인 티켓은 그 시점 수행자를 보존한다 (소급 수정 금지)

### 5. 남의 작업과 겹쳤는지 본다

**남의 브랜치에서 진행 중인 작업과 겹치면 나중에 시작한 쪽이 물러난다.**

같은 티켓·같은 파일을 두 사람이 다르게 고치고 있으면, 먼저 손댄 쪽을 살리고 자기 변경을 되돌린다.
조용히 덮어쓰면 머지 충돌이 "수정 vs 수정" 에서 "수정 vs 삭제" 로 커진다.

```bash
git log --format='%an %s' origin/<남의브랜치> ^origin/main | head
```

### 6. 나머지 두 곳

- `_project/STATE.md` — 다음 세션이 이어받을 상태 (비공개)
- `jekyll/open-items.markdown` — 이번에 정하지 못한 것.
  되돌리기 어려운 선택은 `_project/decisions/NNN-제목.md` 에 **맥락 / 선택지 / 결정 / 근거 / 되돌리는 법** 으로

### 7. 확인

```bash
cd jekyll && bundle exec jekyll build && cd ..
python3 scripts/check_site_links.py jekyll/_site
python3 scripts/check_session_end.py
```

## 하지 않는 것

- **커밋·푸시는 사용자가 명시적으로 요청할 때만 한다** (CLAUDE.md §7)
- 남의 티켓 파일을 임의로 고치지 않는다. 담당이 갈리면 티켓을 쪼갠다
- 확인만 하고 아무것도 바꾸지 않은 세션(질문 답변·조사)은 기록하지 않아도 된다
