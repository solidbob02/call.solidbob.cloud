# 009 — 카드 생성 모델을 EXAONE 3.5 2.4B(Ollama 서빙)로 교체

**작성일**: 2026-08-26
**상태**: 확정

## 맥락

[3.1절](/docs/03/)은 카드 요약 생성(B-4) 모델로 `EleutherAI/polyglot-ko-1.3b`급 소형
모델을 HuggingFace Transformers로 직접 로드해 쓰기로 했었다(`_project/decisions`
이전 기록 없음 — 3.1절 원문에 명시). 4주차 검색 품질 작업을 앞두고 실제로 로드해서
추론 속도를 측정했다.

## 실측 — polyglot-ko-1.3b (HF Transformers, MPS, float16)

프롬프트: 지식베이스 실제 조항(`FIN-TERM-2.2`, 부정사용 보상 기준)을 상담원이 읽을 수
있게 요약하는 B-4 시나리오 그대로. `scripts/test_generation_latency.py`.

| 지표 | 100토큰 | 250토큰 |
|---|---|---|
| 첫 토큰(TTFT, 웜) | 121~136ms | 130~136ms |
| 전체 생성 | 2.90~3.27s | **7.62~7.72s** |
| 처리량 | ~33 tok/s | ~33 tok/s |

**250토큰 기준 7초 중후반은 목표(3~5초)를 크게 초과**한다. 게다가 `polyglot-ko-1.3b`는
instruction 튜닝이 안 된 베이스 모델이라 "요약해줘" 지시를 따르지 못하고 원문을 그대로
반복 출력했다 — 속도뿐 아니라 품질도 실패.

## 대안 비교 — Ollama(llama.cpp/GGUF) 서빙, 같은 프롬프트로 250토큰 강제 생성

사용자 지시로 **중국 출처 모델은 제외**했다(Qwen 계열 등). `scripts/test_ollama_latency.py`.

| 모델 | 출처 | TTFT | 250토큰 전체 | 처리량 | 비고 |
|---|---|---|---|---|---|
| `llama3.2:3b` | Meta 🇺🇸 | 797ms | 2.75s(111토큰, 자연종료) | 57 tok/s | 지시 이행 불완전(불필요한 서두, 목록화) |
| **`exaone3.5:2.4b`** | **LG AI Research 🇰🇷** | **141ms** | **3.63s (250토큰 강제 도달)** | **71.6 tok/s** | **지시 정확히 이행, 자연스러운 한국어, 예시 포함** |

(참고, 제외됨) `qwen3:4b`는 기본 "thinking" 모드가 켜져 있어 250토큰 예산을 추론에
전부 소비하고 실제 답을 못 냈다 — `think:false`를 API에 지정해도 원시 영어 추론
텍스트가 그대로 `response`로 새어 나왔다. 이 문제 하나만으로도 지연시간이 중요한
실시간 어시스트 용도에는 reasoning 모델 계열이 부적합함을 확인했다.

## 결정

**카드 요약 생성(B-4) 모델을 `exaone3.5:2.4b`로, 서빙은 Ollama로 교체한다.**

- 250토큰 실측 3.63s로 목표(3~5초) 충족
- 지시 이행·한국어 품질 모두 `polyglot-ko-1.3b`·`llama3.2:3b`보다 우수
- 로컬 GGUF(Q4 기준) 약 1.6GB — 개발 환경 M4 16GB에서도 여유, AWS 배포 시 가장 가벼운 축
- LG AI Research(한국) 출신 — 사용자의 "중국 모델 제외" 조건 충족

## 근거

- 사용자가 실측 결과(7초 중후반)를 보고 "모델을 바꿔야 할 것 같다"고 명시적으로 지시,
  대안 실측 후 "엑사원 말고... exaone3.5:2.4b로 가자"로 확정.
- HuggingFace + Ollama 조합은 사용자가 직접 지정한 서빙 스택("우리 허깅페이스 + 올라마
  조합이고 AWS 올려서 진행할 것").

## 스택 불변 원칙과의 관계

[아키텍처 3.1절](/docs/03/) 원문은 "목록 밖 도구 없음"을 전제로 HuggingFace
Transformers만 명시했다. **Ollama는 그 목록에 없던 도구다.** 다만 상용 API가 아니라
로컬/오픈 웨이트 서빙 도구이고, 사용자가 직접 이 조합을 지시했으므로 예외로
받아들인다 — [보완지시서 2번](https://github.com/solidbob02/call.solidbob.cloud)이
GPU 미확보 시 폴백을 이미 열어둔 것과 같은 성격의 실용적 조정이다.

## 되돌리는 법

`03-아키텍처.markdown` 3.1절의 생성 모델 문단과 도구 매핑 표에서 Ollama 행을 지우고
`polyglot-ko-1.3b` + HuggingFace Transformers 직접 로드로 되돌린다.

## 후속 — EXAONE 4.0 1.2B로 재교체 (2026-08-26, 같은 날 추가 확정)

사용자가 별도로 Claude Opus에게 5개 역할 전부의 모델을 다시 추천받았고, 검증 결과
`EXAONE-4.0-1.2B`(Ollama)가 이 문서의 `exaone3.5:2.4b`보다 실측상 더 빠르고
가벼우면서 품질도 동등해 **교체했다.** 이 문서의 "Ollama 채택" 근거·"목록 밖 도구
예외" 판단은 그대로 유효하고, 구체적 모델 선택만 바뀌었다. 상세:
`_project/decisions/010-AI-모델-구성-확정.md`(임베딩·NER·분류기 등 나머지 모델
구성도 함께 확정).

## 영향받는 범위 — 아직 결정 안 된 것

같은 날 사용자가 "임베딩 모델 제외하고 모두 바꿀 예정"이라고 밝혀, 컴플라이언스
분류기 베이스(`beomi/KcELECTRA-base`)·NER 모델(`monologg/koelectra-base-v3-naver-ner`)
교체도 논의 중이다. **이 두 모델은 아직 교체를 확정하지 않았다** — 이유: 생성 모델과
달리 인코더 기반 분류·NER 모델은 파인튜닝 헤드가 있어야 실제 정확도를 잴 수 있는데,
지금은 파인튜닝 헤드 자체가 없어 "실측"이 불가능하다(속도만 재는 것은 의미가 제한적).
후보와 판단 재료는 `jekyll/open-items.markdown`에 남긴다.
