**②는 원안(「코어 포트 절반 이상이 501 을 벗어나면」)을 쓰지 않았다.** 그 조건은 지금 상황에서
너무 헐겁다 — 트리거 배선 하나만 붙어도 2/4 가 되어, **컴플라이언스와 D-1~D-3 이 손도 안 댄
상태로 확장이 열린다.** 「**전부** 501 을 벗어나고 **6.1절에 미달(❌) 항목이 없을 것**」으로 좁혔다.
동결 취지(코어를 미루지 않는다)는 지키면서 끝나는 지점은 그대로 생긴다.
**별도 결재 절차는 두지 않는다** — ②는 하네스 출력으로 판정되므로 사람이 승인할 자리가 없다.

**④는 (a) 담당자별 번호대**를 골랐다. (b)(날짜+슬러그)가 더 단순하지만 기존 참조 20건을
고쳐야 하고, 이 문서 자체가 번호로 참조되고 있다.

### 함께 처리한 것 2건 (원안에 없음)

- **도메인 4종 조항에서 "예시로도" 를 뺐다** (`CLAUDE.md §1`). 데이터·골든셋·지식베이스에 새 도메인을
  만들지 않는다는 취지는 유지하되, **문서·발표의 예시까지 막을 이유는 없다.**
- **`CLAUDE.md §3` 의 `server/.importlinter(계약 3종)` 오기를 4종으로 정정**했다(실제 4종).

### 반영하지 않은 것

- **B-0 목표 `≥0.95` 는 손대지 않았다.** n=14 에서는 14/14 만점 말고 통과가 없어 판정 자체가

  [미결 항목](/open-items/)에 등록했다.

## 1. 담당 디렉터리 경계 — 「배선」까지 막고 있다 ⭐ 가장 급함

### 지금

`decisions/012`: *"디렉터리 경계를 그대로 담당 경계로 쓴다."*
`ai/` 는 류준, `server/` 는 장민석. *"경계에 걸친 작업은 함께 정한다"* 고만 돼 있고
**무엇이 「경계에 걸친 작업」인지 정의가 없다.**

### 오늘 실제로 든 비용

2026-08-27 장민석 세션에서 **경계 때문에 멈춘 것이 6건**이다. 그중 하나:

> **평가 하네스에 C-5·F-2 를 꽂는 일.** 하네스 `main()` 이 `Ports()` 를 빈 채로 불러
> 전부 「측정 불가」로 보고된다. 장민석이 시험 삼아 꽂아 돌린 결과 —
> `masking {miss_count: 0, n: 12}` · `closure_gate {accuracy: 1.0, n: 16}`.
> **고칠 곳은 `main()` 한 곳, 실질 3줄.** 그런데 `ai/apps/evaluation/` 이라 손대지 못했다.
>
> 결과: **이 프로젝트는 아직 문서에 쓸 수치가 0개인데, 낼 수 있는 수치를 안 내고 있다.**

### 제안 — 「소유」와 「배선」을 가른다

| 종류 | 예 | 규칙 |
|---|---|---|
| **소유 — 담당자만** | 알고리즘·판정 로직·모델·청킹·검색 전략·도메인 규칙 | 그대로 유지 |
| **배선 — 둘 다 가능** | 포트 주입, `main()`·프로바이더 배선, import 경로, 문서/주석의 참조 갱신, 남이 만든 구현을 꽂는 일 | **사전 합의 없이 가능.** 커밋 메시지에 명시 + PR 에 해당 담당자 태그 |

**안전장치는 이미 있다.** `.importlinter` 계약 7종(server 4 + ai 3)이 구조 위반을 잡는다 —
계약이 KEPT 면 배선은 구조를 깨지 않는다. 사람이 지켜야 할 것을 도구가 이미 지키고 있다.

> ⚠ 이건 `decisions/012` 를 **철회하는 게 아니다.** 경계는 유지하되 *"경계에 걸친 작업"* 의
> 빈칸을 채우는 것이다. 류준이 지정한 담당 구분("내가 AI, 민석님이 server")은 그대로다.

## 2. F·G·H·I 동결 — 해제 조건이 사실상 없다

### 지금

`CLAUDE.md`: *"코어 기준선을 통과하지 못했다면 F·G·H·I 를 착수하지 않는다."*

### 문제

**기준선이 0개다.** 하네스가 전부 「측정 불가」라 *"통과"* 를 판정할 방법이 없다 →
**해제 조건이 없는 영구 동결**이다. 확장 아이디어가 논의 단계에서 멈춘다.

### 제안 (원안)

> 코어 기준선을 통과하지 못했다면 F·G·H·I 를 착수하지 않는다.
> **단, 아래 중 하나면 해제한다 —**
> **① 4주차 검증 체크포인트에서 팀이 재검토해 승인한 경우**
> **② 코어 포트(트리거·검색·컴플라이언스·D-1~D-3) 중 ~~절반 이상~~이 501 을 벗어난 경우**

동결 취지(코어를 미루지 않는다)는 유지하면서 **끝나는 지점을 만든다.**

### 확정 — ②의 조건을 좁혔다 (2026-08-27)

**「절반 이상」은 채택하지 않았다.** 제안이 작성된 시점 이후 PR #36 이 머지되며 트리거(B-1)
구현이 들어왔고, 그 결과 **트리거 배선 하나만 붙어도 2/4 = 절반이 되어 자동 해제**된다.
그 시점에도 **컴플라이언스(C-1~C-4)와 D-1~D-3 은 모듈 자체가 없다**(`ai/apps/compliance/`·
`server/apps/postcall/` 미생성, 2026-08-27 확인). 코어 절반이 비어 있는 채로 확장이 열린다.

> 코어 기준선을 통과하지 못했다면 F·G·H·I 를 착수하지 않는다.
> **단, 아래 중 하나면 해제한다 —**
> **① 4주차 검증 체크포인트에서 팀이 재검토해 승인한 경우, 또는**
> **② 코어 포트(트리거 B-1 · 검색 B-2~B-3 · 컴플라이언스 C-1~C-4 · 통화 후 처리 D-1~D-3)가
>    전부 501 을 벗어나고, [6.1절 지표](/docs/06/)에 미달(❌) 항목이 없는 경우**

**②는 하네스 출력으로 판정되므로 별도 결재 절차를 두지 않는다.** 사람이 승인할 자리를 만들면
그 자리가 다시 병목이 된다 — 이 문서가 없애려는 것과 같은 종류의 문제다.

⚠ **지금 기준으로는 해제되지 않는다.** 6.1절에 B-0 가 `0.857 ❌`(목표 0.95)로 남아 있고
코어 포트 4개 중 3개가 501 이다. **그것이 이 조건의 의도다** — 판정이 가능해졌을 뿐,
통과한 것은 아니다.

## 3. 기능 ID — 새 아이디어를 올릴 자리가 없다

### 지금

`rfp-harness.md §1`: *"기획서의 기능 ID 를 그대로 요구사항 ID 로 쓴다. 별도 접두어를 새로 만들지 않는다."*

### 문제

기획서에 없는 아이디어는 **붙일 ID 가 없어 제안 자체가 막힌다.** 실제로 2026-08-27
"상담 중 고객에게 자료 발송" 논의가 여기서 멈췄다. 접두어 난립을 막으려는 규칙인데
**제안을 막는 부작용**이 생겼다.

### 제안

**`X-` 접두어를 「미결 항목 전용」으로 연다.** `X-1`·`X-2` 는 아직 채택되지 않은 후보를
가리키고, 채택되면 기획서에 정식 ID 를 받으며 `X-` 는 버린다.
**코드에는 `X-` 를 쓰지 않는다** — 접두어 난립 방지 취지는 그대로 지켜진다.
