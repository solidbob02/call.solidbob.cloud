# 023. 협의를 절차로 요구하는 규칙을 없앤다 (008 철회 포함)

- **날짜**: 2026-08-27
- **상태**: 채택
- **관련**: `_project/decisions/008-검증-체크포인트-방식-전환.md`(**이 문서로 철회**),
  `_project/decisions/022-백엔드-생산성-규칙-완화.md`(장민석 제안 — **1번을 이 결정이 상당 부분 해소한다**),
  `_project/decisions/012`, `jekyll/docs/07-역할분담.markdown`, `jekyll/docs/08-마일스톤.markdown`,
  `ai/CLAUDE.md`, `server/CLAUDE.md`

## 맥락

협의를 **문서상의 절차로** 요구하는 규칙이 두 갈래 있었다. 방향은 서로 반대였다.

| | 규칙 | 방향 |
|---|---|---|
| ⓐ | `ai/CLAUDE.md`·`server/CLAUDE.md`·7.2절 — "계약을 건드릴 때는 상대와 **합의한다**" | 협의를 **요구** |
| ⓑ | 7.4절 + `decisions/008` — "완료 즉시 개별 검수받지 않고 **4주차 말 체크포인트에 모아서**" | 협의를 **미룸** |

ⓑ는 ⓐ가 만든 대기 시간을 완화하려고 만든 것이다. 즉 **절차가 절차를 낳고 있었다.**

## 결정

**둘 다 없앤다.** 대신 규칙이 남기는 것은 하나뿐이다 —
**"손대기 전에 무엇이 깨지는지 먼저 확인한다"**(`grep` 으로 영향 범위 확인).

누구와 어떻게 맞출지는 문서가 정하지 않는다.

## 장민석 제안(022) 1번과의 관계

장민석이 같은 날 `decisions/022` 로 **"담당 경계가 배선까지 막고 있다"** 를 제안하며
**"특히 1번은 류준 동의가 필요하다"** 고 남겼다. 거기 적힌 실제 비용:

> 평가 하네스에 C-5·F-2 를 꽂는 일. 고칠 곳은 `main()` 한 곳, 실질 3줄인데
> `ai/apps/evaluation/` 이라 손대지 못했다. 시험 삼아 꽂아 돌린 결과는
> `masking {miss_count: 0, n: 12}` · `closure_gate {accuracy: 1.0, n: 16}` 였다.

**"경계에 걸친 작업은 함께 정한다"** 는 문장이 그 3줄을 막고 있었다.
이 결정으로 그 문장이 사라지므로 **제안 1번의 핵심 마찰은 해소된다.**

다만 022 의 나머지(2. F·G·H·I 동결 해제 조건, 3. 기능 ID 확장, 4. 결정 번호 선점)는
**이 결정이 다루지 않는다** — 별개 사안이고 여전히 팀 확인 대기다.

## 근거

**네 사람이 같은 공간에서 일한다.** 협의가 필요하면 그 자리에서 말로 맞추면 된다.
문서에 절차를 적어 두면 실제로는 이렇게 된다.

- 말로 이미 끝난 일을 문서 절차에 맞추느라 다시 적는다
- 절차를 안 지켜도 아무 일이 없어서 규칙만 죽은 채 남는다
  (`CLAUDE.md` §0.5 가 "진행 기록 규칙은 지금까지 가장 자주 뚫린 규칙"이라고 적어 둔 것과 같은 현상)
- 지키려 들면 대기 시간이 생기고, 그걸 풀려고 또 규칙(ⓑ)을 만든다

**규칙은 사람이 못 하는 것만 맡는 게 낫다.** 사람이 놓치는 것은 "이걸 바꾸면 저쪽이 깨진다"는
사실이고, 그건 `grep` 한 번으로 잡힌다. 반면 "누구와 상의할까"는 사람이 훨씬 잘 판단한다.

## 지운 것

| 위치 | 무엇 |
|---|---|
| `ai/CLAUDE.md` §6 | "계약을 건드릴 때는 양쪽을 함께 보고 장민석과 **합의한다**" |
| `server/CLAUDE.md` §5 | "포트·DTO 를 바꿀 때는 `../ai/` 를 먼저 grep 하고 류준과 **합의한다**" |
| `jekyll/docs/07-역할분담.markdown` 7.2절 | "경계에 걸친 작업은 여전히 **둘이 함께 정한다**" |
| `jekyll/docs/07-역할분담.markdown` **7.4절** | 검수 방식 절 **전체 삭제** |
| `jekyll/docs/08-마일스톤.markdown` | "4주차 말 — 팀 전체 검증 체크포인트" 절 **전체 삭제** |
| `jekyll/open-items.markdown` | 검수 방식 확정 항목 → 이 결정으로 교체 |
| `w1-db-schema` · `w2-golden-set-50` | "체크포인트에서 처리한다" → "검수 절차 없음" |

`grep` 으로 영향 범위를 먼저 보라는 문장은 **남겼다.** 그건 협의 절차가 아니라 사고 절차다.

## 남는 것 — 검수 대기 항목

`decisions/008` 이 "4주차 말에 모아서 처리"하기로 했던 항목들은 **처리 시점이 없어졌다.**

- DB 스키마 4인 승인 (`w1-db-schema`)
- 골든셋 F-2 케이스 교차검수 (`w2-golden-set-50`)

두 티켓 본문에 **"검수 절차 규칙이 없어졌다"** 고 적어 두었다. 승인이 실제로 필요하면
그 자리에서 말로 맞춘다. **"검수 없이 확정된 것처럼 기록하지 않는다"** 는 원칙 자체는
`CLAUDE.md` 절대 원칙에 그대로 살아 있다 — 이 결정이 바꾼 것은 **절차이지 정직성이 아니다.**

기록에 안 남아 나중에 서로 다르게 기억하는 일이 반복될 때.
