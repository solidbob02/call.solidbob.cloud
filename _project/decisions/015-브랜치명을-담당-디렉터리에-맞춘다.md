# 015. 브랜치 이름을 담당 디렉터리 이름에 맞춘다 (`backend`→`ai`, `ai`→`server`)

- **날짜**: 2026-08-26
- **상태**: 채택 · **적용 완료** (2026-08-26)
- **관련**: `_project/decisions/011-브랜치-정책과-main-보호.md`(넷 유지 — 유지된다),
  `_project/decisions/012-백엔드-ai-server-담당-분리.md`(이 문서가 그 ⚠ 절을 해소한다),
  `CLAUDE.md` §1·§7, `.claude/rules/rfp-harness.md` §2, `.github/workflows/test.yml`

## 맥락

`decisions/012` 로 백엔드·AI 담당을 디렉터리 경계로 나눈 뒤, 브랜치 이름이 **다른 사람을
가리키는** 상태가 남았다.

| | 류준 | 장민석 |
|---|---|---|
| 브랜치 (이전) | `backend` | `ai` |
| 디렉터리 | `ai/` | `server/` |

즉 **장민석의 `ai` 브랜치에서 고치는 것은 `server/`** 였다. `decisions/012` 는 이것을
"팀 확인 전까지는 바꾸지 않는다"로 남겼는데, 이유는 **브랜치명을 바꾸면 main 룰셋의 필수
통과 검사 이름까지 함께 고쳐야 한다**는 것이었다.

## 결정

**브랜치를 개명한다.** `backend` → `ai`(류준) · `ai` → `server`(장민석).
브랜치는 여전히 넷이다 — `PM` / `ai` / `server` / `frontend` (`decisions/011` 유지).

## 근거

**`decisions/012` 가 미룬 이유는 사실이 아니었다.** main 룰셋의 필수 통과 검사 이름은
`test.yml` 의 **job 이름**(`server`·`ai`·`jekyll`)이지 브랜치 이름이 아니다. 확인:

```bash
gh api repos/solidbob02/call.solidbob.cloud/rules/branches/main \
  --jq '.[] | select(.type=="required_status_checks") | .parameters.required_status_checks'
# [{"context":"jekyll"},{"context":"ai"},{"context":"server"}]
```

브랜치 이름이 실제로 걸려 있던 곳은 **`test.yml` 의 push 트리거 목록 하나뿐**이었다.
룰셋(admin 권한 필요)은 건드릴 필요가 없었다.

이름이 사람을 엇갈리게 가리키는 상태는 그 자체로 비용이다 — 진행 기록·PR·티켓에서 `ai` 가
누구를 뜻하는지 매번 되짚어야 하고, `decisions/012` 는 그 혼동을 막으려고 표 하나를 통째로
할애하고 있었다.

## 적용 결과 (2026-08-26)

```
git branch -m backend ai && git push -u origin ai && git push origin --delete backend   # 류준
(장민석은 ai → server 로 같은 작업을 먼저 마쳤다)
```

- 삭제 전 확인: `origin/backend`·구 `origin/ai` 모두 `origin/main` 의 **조상**이었다
  (`git merge-base --is-ancestor`). 미머지 커밋 0건 — 지운 것으로 잃은 작업이 없다.
- `test.yml` 트리거: `[main, PM, backend, ai, frontend]` → `[main, PM, ai, server, frontend]`
- 룰셋·`.github/branch-protection.json`: **변경 없음** (job 이름 기준이므로)

## ⚠ 옛 기록을 읽을 때

**`ai` 라는 이름이 사람을 갈아탔다.** 2026-08-26 이전 기록(`progress.markdown`·`STATE.md`·
PR #15·#22·#27)의 `ai` 브랜치는 **장민석**이고, 그날 이후는 **류준**이다. 같은 날짜의
`backend` 는 전부 류준이다. 옛 기록은 그 시점의 사실이므로 고치지 않는다(절대 원칙 8).

## 되돌리는 법

```bash
git branch -m ai backend && git push -u origin backend && git push origin --delete ai
```

`test.yml` 트리거 목록을 되돌린다. 룰셋은 손대지 않는다.
`decisions/012` 의 ⚠ 절(이름 엇갈림)이 다시 유효해진다.
