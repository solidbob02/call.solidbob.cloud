# 010 — AI 모델 구성 전면 확정 (Opus 교차검증 반영)

**작성일**: 2026-08-26
**상태**: 확정

## 맥락

`_project/decisions/009`에서 생성 모델(B-4)을 `polyglot-ko-1.3b` → `exaone3.5:2.4b`
(Ollama)로 교체했다. 같은 날 사용자가 별도로 **Claude Opus에게 같은 조건(개발 환경
M5 24GB·M4 16GB, HuggingFace+Ollama 조합, AWS 배포, 중국 모델 제외)으로 5개 역할
전부의 모델을 다시 추천받았다.** 그 결과를 검토·검증한 뒤 최종 구성을 확정한다.

## Opus 추천안과 실제 검증 결과

Opus 추천을 그대로 받아들이지 않고, **검증 가능한 주장은 전부 직접 확인**했다
([CLAUDE.md 절대 원칙 2](/CLAUDE.md) — 측정하지 않은 수치를 기록하지 않는다).

| 역할 | 추천 모델 | Opus 근거 | 검증 결과 |
|---|---|---|---|
| 임베딩(B-2) | `nlpai-lab/KoE5` | ko-sroberta-multitask는 128토큰 상한이라 청크 15~28% 잘림 | **사실.** `ko-sroberta-multitask/sentence_bert_config.json`에 `max_seq_length: 128` 확인(아키텍처는 512 지원하지만 SentenceTransformer로 쓰면 128에서 잘림). 지식베이스 조항 103건 직접 토크나이즈: **8.7%가 128토큰 초과**(Opus 주장 15~28%보다 낮지만 방향은 일치 — 청킹 전략이 아직 미정이라 정확한 비교 불가). KoE5는 `sentence_bert_config.json` 자체가 없어 512 그대로 사용. 1024차원(768→1024 변경 필요 주장도 정확), MIT 라이선스 확인 |
| 생성(B-4) | `LGAI-EXAONE/EXAONE-4.0-1.2B` | 최신 한국어 instruct, 메모리 절반이라 M4 16GB에 여유 | **실측 완료 — 채택.** 아래 절 참고 |
| 생성 대조군(6주차) | `kakaocorp/kanana-1.5-2.1b-instruct-2505` | 환각 건수 비교용, Apache 2.0 | 모델 존재·라이선스 확인(6,799 다운로드). **로컬에 못 받음** — Ollama 공식 라이브러리에 없고 `hf.co/kakaocorp/...-GGUF` 레포도 못 찾음. 6주차 착수 시 재시도 |
| NER(C-5) | 유지 + 주소 규칙 보강 | P6(인명)엔 맞지만 P7(상세주소)은 태그가 없음 | 타당한 관찰 — NAVER NER 코퍼스는 LOC(지명) 태그는 있어도 상세주소(번지·동호수) 전용 태그는 없다. 유지 |
| 분류기(C-1~4·B-0) | 유지 + `klue/roberta-base` 대조군 | KcELECTRA는 댓글 학습이라 STT 오탈자에 강함, 5주차 오류 내성 실험과 맞음 | 타당 — 유지 |

## 생성 모델 — EXAONE 4.0 1.2B로 재확정 (decisions/009 갱신)

`decisions/009`에서 확정한 `exaone3.5:2.4b`를 **`LGAI-EXAONE/EXAONE-4.0-1.2B`
(Ollama, `hf.co/LGAI-EXAONE/EXAONE-4.0-1.2B-GGUF`, 812MB)로 다시 교체한다.**

같은 프롬프트·250토큰 강제 생성으로 실측(`scripts/test_ollama_latency.py` 방식):

| | thinking 기본(켜짐) | thinking 끔(`think:false`) |
|---|---|---|
| 결과 | **빈 응답 또는 원시 영어 추론만 출력** (Qwen3와 동일한 실패 모드) | 정상 |
| 250토큰 전체 | — | **2.01~2.14s** (2회 실행) |
| TTFT | — | 19~157ms |
| 처리량 | — | ~126 tok/s |

`exaone3.5:2.4b`(3.63s, 71.6 tok/s)보다 **약 1.7배 빠르고 크기는 절반**이다. 품질도
동등하거나 더 나음(구체적 예시를 든 자연스러운 한국어 설명, 정확히 멈춤).

**중요 — 반드시 지킬 것**: EXAONE 4.0은 하이브리드 reasoning 모델이라 기본 상태로는
`num_predict` 예산을 추론에 다 쓴다. **`/api/chat` 엔드포인트 + `"think": false`
옵션을 반드시 함께 써야 한다** — `/api/generate` 엔드포인트에서는 `think:false`가
반영되지 않는 것을 실측으로 확인했다(Qwen3에서 먼저 겪었던 것과 같은 계열의 함정).

**라이선스**: `EXAONE AI Model License Agreement 1.2 - NC`(비상업). 원문 확인 완료.
8주 팀 포트폴리오 프로젝트라 문제없다고 판단하지만, 이후 실제 상용화 논의가 나오면
재검토가 필요하다.

## 결정

| 역할 | 이전 | 이후 |
|---|---|---|
| 임베딩(B-2) | `ko-sroberta-multitask` (768차원, 128토큰 상한) | **`KoE5`** (1024차원, 512토큰) |
| 생성(B-4) | `exaone3.5:2.4b` | **`EXAONE-4.0-1.2B`** (Ollama, `think:false` + `/api/chat` 필수) |
| 생성 대조군 | (없음) | `kanana-1.5-2.1b-instruct` — 6주차, 아직 못 받음 |
| NER(C-5) | `koelectra-ner` | **그대로 유지**, P7은 규칙 보강 예정(미착수) |
| 분류기(C-1~4·B-0) | `KcELECTRA-base` | **그대로 유지** + `klue/roberta-base` 대조군 추가(5주차 비교용) |

## 근거

- 사용자가 Opus 교차검증 결과를 받아왔고, 제가 검증 가능한 항목(모델 존재 여부·설정
  파일·라이선스·실제 추론)을 전부 확인한 뒤 "Opus 추천 그대로 가고 EXAONE도 1.2B로
  바꾸자"고 확정.
- EXAONE 4.0 1.2B가 3.5 2.4B보다 실측상 명확히 빠르고 가벼우며 품질도 손색없어,
  교체 근거가 충분하다.

## 아직 실측하지 않은 것 (Opus도 명시한 전제)

Opus 스스로 "이건 전부 가설입니다. 확정은 골든셋 측정으로"라고 밝혔다. 이번에 확인한
것은 **① 모델·설정 파일이 실제로 주장대로 존재하는지 ② 생성 모델의 레이턴시·기본
품질**이다. 다음은 아직 측정 전이다:

| 항목 | 측정 시점 |
|---|---|
| KoE5 vs ko-sroberta-multitask 실제 Recall@5 차이 | 4주차(임베딩 착수) |
| KcELECTRA vs klue/roberta-base 오류 내성 비교 | 5주차 |
| EXAONE-4.0-1.2B vs kanana-1.5-2.1b 환각 건수 비교 | 6주차 |
