# 019 — C-5 마스킹 담당을 정성윤 → 장민석으로 이관

**날짜**: 2026-08-27
**상태**: 확정 (정성윤 부재 중 결정 — 복귀 후 재협의 가능)

## 맥락

C-5(개인정보 실시간 마스킹)는 **코어 사수 항목**이고 절대 규칙(누락 0건)이 걸려 있다.
`server/` 파이프라인 11개 엔드포인트가 전부 배선됐지만, `MaskingPort` 구현이 없어
`POST /hub/transcripts` 가 501 이다. **전사가 들어오지 못하므로 그 뒤 파이프라인 전체가
데이터를 받지 못한다** — 지금 프로젝트를 막고 있는 단일 지점이다.

확인해보니 **C-5 는 티켓조차 만들어진 적이 없다.** 담당(정성윤)에게 배정된 6건 중
마스킹 관련은 하나도 없고, `server/apps/masking/` 디렉터리도 존재하지 않는다.

## 선택지

| | 방법 | 문제 |
|---|---|---|
| A | 정성윤 복귀까지 기다린다 | 부재 기간이 불확실하고, 그동안 파이프라인 검증이 스텁에 머문다 |
| **B** | **장민석이 넘겨받는다** | 팀이 정한 부하 분산 조치(7.2절)를 바꾸는 것 |
| C | 임시 통과 구현(마스킹 없이 흘려보내기) | **SEC-1 위반.** 그 경로가 생기는 순간 원문이 새는 길이 된다 |

## 결정

**B — 장민석이 C-5 를 맡는다.** 사용자(장민석) 결정, 2026-08-27.

## 근거

1. **보존할 수행 기록이 없다.** `CLAUDE.md` 칸반 규칙은 *"담당이 바뀌면 착수 여부로 갈린다.
   아직 `todo` 인 티켓은 보존할 수행 기록이 없으므로 새 담당자로 옮긴다"* 고 정한다.
   C-5 는 티켓도 코드도 없어 **착수 전** 상태다.
2. **디렉터리 경계와 맞는다.** `server/apps/masking/` 은 장민석 담당 디렉터리 안이다.
   `rfp-harness.md` 도 *"예외적으로 코어 내 배치"* 라고 적어 이 위치를 이미 인정하고 있었다.
   `decisions/012`(디렉터리 경계 = 담당 경계) 이후로는 오히려 이쪽이 일관된다.
3. **C 는 선택지가 아니다.** 절대 원칙 3(누락 0건)과 SEC-1 을 동시에 깬다.

## 이 결정이 바꾸는 것

- `.claude/rules/rfp-harness.md` §2 R&R 표 · §3.1 C-5 행의 담당자
- `server/CLAUDE.md` 담당 표기

**정성윤에게 남는 것**: 게이트웨이(A-1·A-2)·인프라·CI 운영. 7.2절이 걱정한 "류준 단독
과부하"는 4인 개편으로 이미 해소됐고, C-5 를 정성윤에게 둔 것은 그 시절의 완화 조치였다.

## 되돌리는 법

정성윤이 복귀해 다시 맡기로 하면 위 두 문서의 담당자를 되돌리고 티켓 `assignee` 를 바꾼다.
**코드는 옮기지 않아도 된다** — `server/apps/masking/` 위치는 어느 쪽이 맡든 같다.

## ⚠ 알려야 할 것

이 결정은 **정성윤 부재 중에 내려졌다.** 복귀하면 가장 먼저 공유한다 —
본인 담당 항목이 사라진 것을 나중에 발견하게 두지 않는다.
