# 002. 인터페이스 스키마 3종(전사·카드·종결) 확정

- **날짜**: 2026-08-25
- **상태**: 채택
- **관련**: `jekyll/docs/07-역할분담.markdown` 7.3절, `db/docs/ERD.md`

## 맥락

병렬 작업(정성윤 게이트웨이·마스킹, 류준 검색·생성·컴플라이언스, 장민석 프론트)의 전제 조건으로
전사 이벤트·추천 카드·종결 판정 3종 스키마를 1주차에 고정해야 했다. 초안은 7.3절에 있었고,
카카오톡으로 컨펌을 요청했다.

## 결정

7.3절 초안을 **필드명·값 정의 변경 없이 그대로 확정**한다.

```json
// 전사 이벤트 (마스킹 적용 후)
{
  "call_id": "c_001",
  "speaker": "customer",
  "text": "카드번호는 **** 입니다",
  "masked": [{"type": "P2", "span": [7, 11]}],
  "is_final": true,
  "utterance_end_ms": 3100
}

// 추천 카드
{
  "call_id": "c_001",
  "trigger_at_ms": 3150,
  "cards": [
    {
      "title": "프로모션 할인 적용 시점 안내",
      "summary": "신규 가입 할인은 가입 다음 달 청구서부터 반영됩니다.",
      "source": {"doc": "요금제약관", "clause": "3.2"},
      "score": 0.87
    }
  ],
  "internal_latency_ms": 780,
  "e2e_latency_ms": 1240

// 종결 판정 (F-2)
{
  "call_id": "c_001",
  "closure_type": "해지",
  "reason": "고지 완료",
  "evidence": {"위약금_안내": true, "잔여할부_안내": false, "고객확인_기록": false},
  "verdict": "blocked",
  "missing": ["잔여할부_안내", "고객확인_기록"],
  "source": {"doc": "응대매뉴얼", "clause": "7장"}
}
```

## 컨펌 요청 시 함께 전달한 참고 사항

- `masked` 필드: 같은 날 실측한 Google STT 숫자 출력 테스트(`scripts/test_stt_v3.py`) 결과, 숫자 정규화가
  케이스마다 다르게 나온다(완전 정규화/부분 정규화/오인식 혼재). C-5 마스킹 정규식이 "숫자만 나온다"고
  가정하면 안 된다는 점을 정성윤에게 공유했다.
- `is_final` 필드: 스트리밍 지연 실측(`scripts/test_stt_v4_streaming.py`) 결과, 20초 발화에 interim이
  199건, 발화 종료 후 최종 결과까지 +346ms 걸렸다. 장민석의 자막 렌더링 갱신 빈도 설계에 참고 자료로 전달했다.

## 결과 / 되돌리는 법

이 스키마가 확정되면서 다음 파트가 이 계약을 기준으로 병렬 진행된다.

- 정성윤: `services/gateway/`(전사 이벤트 생성), `services/core/masking/`(masked 필드 채우기)
- 류준: `services/core/retrieval/`·`services/core/generation/`(cards 배열 생성)
- 장민석: `apps/dashboard/`(3종 모두 소비)

스키마를 바꾸려면 이 파일에 새 결정을 추가(대체하지 않음)하고, 위 3개 디렉토리의 소비 코드를 함께 갱신해야 한다.
