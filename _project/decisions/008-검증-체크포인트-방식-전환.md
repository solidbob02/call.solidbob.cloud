# 008 — 건건이 검수 대기 대신, 중간 체크포인트에 모아서 팀 전체 검증

**작성일**: 2026-08-26
**상태**: 확정

## 맥락

지금까지의 진행 방식은 항목마다 "완료 조건에 팀 리뷰·승인 포함"을 걸어왔다 — DB 스키마
("3인/4인 승인 후 마이그레이션 확정", `w1-db-schema.md`), 골든셋 F-2 케이스("작성자가
아닌 사람이 검수", `w2-golden-set-50.md`), 지식베이스("팀 리뷰 후 확정") 등. 이 방식은
검수자가 즉시 대응 가능하다는 전제에서만 성립한다.

그런데 실제로는:

1. **아직 제대로 된 시스템이 구축되지 않았다** — 검수할 실물(실행되는 서비스, 실측
   지표)이 거의 없고, 대부분 설계 문서·데이터 파일 단계다. 지금 건건이 리뷰를 받아도
   "구현이 명세대로 됐는가"를 확인할 대상 자체가 부족하다.
2. **4인 전원이 각자 할 일로 바쁘다** — 정성윤은 인프라·CI, 장민석은 `fastapi/apps/`
   아키텍처, 조서희는 대시보드, 류준은 골든셋·평가 하네스를 동시에 진행 중이다. 매
   완료 건마다 다른 사람의 즉시 검수를 기다리면 대기 시간이 누적된다.

## 결정

**개별 완료 건마다 즉시 검수를 기다리지 않는다.** 대신 작업은 계속 진행하고, **일정
중간 지점에 팀 전체가 모여 그동안 쌓인 것을 한 번에 검증하는 체크포인트**를 둔다.

- 체크포인트 시점: **4주차 말**(검색 품질 스프린트 종료 시점, 5주차 오류 내성 실험
  착수 직전). 가장 어려운 실험 주차(5주차) 들어가기 전에 기반이 맞는지 한 번에
  확인한다는 의미가 있다.
- 기존에 이미 정해져 있던 **6주차 코어 기준선 확인**, **7주차 F-2 중간 체크포인트**는
  그대로 유지한다 — 이번 결정은 그 사이에 "4주차 말 전체 검증"을 하나 더 추가하는
  것이다.
- 체크포인트에서 다룰 것(누적된 검수 대기 항목): DB 스키마 4인 승인(`w1-db-schema.md`),
  골든셋 F-2 케이스 교차검수(`w2-golden-set-50.md`), 그 시점까지 쌓인 지식베이스·
  인터페이스 계약 변경분.

## 근거

- 사용자가 명시적으로 지시: "각자 할 일이 너무 바쁘니 일단 업무 쭉 하다가 중간쯤에
  다같이 검증하는 일정을 두자."
- CLAUDE.md 절대 원칙과 충돌하지 않는다 — "측정하지 않은 수치를 기록하지 않는다"는
  원칙은 유지되고, 이번 결정은 **검수의 시점**만 바꾼다. 검수 없이 확정된 것처럼
  기록하지는 않는다 — 체크포인트 전까지는 계속 "검수 대기" 상태로 정직하게 표시한다.

## 되돌리는 법

건건이 즉시 검수로 되돌리려면 [08절 마일스톤](/docs/08/)의 "4주차 말 전체 검증
체크포인트" 문단을 삭제하고, 각 티켓의 완료 조건에서 "체크포인트에서 일괄 검수"
문구를 원래의 개별 검수 요구로 되돌린다.
