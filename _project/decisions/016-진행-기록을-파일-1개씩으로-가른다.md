# 016. 진행 기록을 "항목 1건 = 파일 1개"로 가른다

- **날짜**: 2026-08-27
- **상태**: 채택 · **적용 완료**
- **관련**: `CLAUDE.md` §0·§0.5·§3·§4, `scripts/check_session_end.py`,
  `scripts/check_progress_log.py`, `.claude/skills/session-log/`

## 맥락

`jekyll/progress.markdown` 이 브랜치를 합칠 때마다 충돌했다. 2026-08-25~26 이틀 동안
**이 파일을 건드린 커밋 37건 중 16건(43%)이 충돌 처리**였고, 작성자는 4명이었다.

"번호(`(44)`, `(45)`)가 겹쳐서"라는 설명이 돌았지만 **틀렸다.** 빈 저장소에서 재현했다.

| 방식 | 결과 |
|---|---|
| 위에 삽입, 번호도 내용도 완전히 다름 (11 vs 12) | ❌ CONFLICT |
| 아래로 append 로 바꿔 봄 | ❌ CONFLICT |
| 항목 1건 = 파일 1개로 분리 | ✅ 자동 병합 |

**원인은 "같은 파일의 같은 위치"다.** `progress.markdown` 은 "최신 항목이 위로" 규칙 때문에
누가 쓰든 front matter 바로 다음 줄에 삽입한다. Git 3-way 병합은 양쪽이 동일한 컨텍스트
사이에 서로 다른 내용을 넣으면 어느 쪽이 먼저인지 판단할 수 없어 무조건 충돌로 넘긴다.
번호는 원인이 아니라 **가중 요인**이다 — 기계적으로 풀 수 있었을 충돌을 "누가 (44)를 가질
것인가"라는 사람의 판단이 필요한 충돌로 바꾼다.

여기에 `CLAUDE.md` §0.5 + `Stop` 훅이 **모든 브랜치가 이 파일을 건드리도록 강제**한다.
파일을 하나라도 고친 세션은 진행 기록을 남겨야 세션이 끝난다. 즉 충돌은 우연이 아니라
구조적으로 보장돼 있었다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 번호를 없애고 시각(`14:30`)으로 | 번호 다툼이 사라짐 | **충돌 자체는 그대로** — 위 실험대로 위치가 같으면 충돌한다 |
| B. 사람마다 파일을 따로 (`progress-ryujun.md` 등) | 충돌 사라짐 | 한 사람 안에서는 여전히 같은 위치 삽입. 팀 전체 시간순 보기가 사라짐 |
| **C. 항목 1건 = 파일 1개 (`_logs/` 컬렉션)** | 충돌이 구조적으로 불가능. `_backlogs/` 에서 이미 검증된 패턴 | 파일 수가 늘어난다(현재 66개) |
| D. 아무것도 안 함 | — | 충돌 반복. 머지할 때마다 사람이 붙어야 한다 |

## 결정

**C.** `jekyll/_logs/` 컬렉션으로 가른다. 파일명은 `YYYY-MM-DD-{seq}-{person}.md`.
`/progress/` 는 이 컬렉션을 읽어 **작성자별 사이드바**(전체 / 정성윤 / 류준 / 장민석 / 조서희)로
렌더링한다. `/kanban/` 과 같은 구조다.

## 근거

- **`CLAUDE.md` §4 가 이미 같은 진단을 내려 두었다** — "세 사람이 하나의 표를 같이 고치면
  병합 충돌이 나므로, 보드를 페이지에 직접 그리지 않는다". 칸반은 이 규칙 덕에 같은 기간
  충돌이 0건이었다. 진행 기록에만 적용되지 않았을 뿐이다.
- `seq` 가 겹쳐도 파일명에 작성자가 들어가 **서로 다른 파일**이 된다. 공유 카운터가 사라진다.
- 정렬은 `date`·`seq` 두 필드가 아니라 **파일 경로**로 한다. Liquid 의 `sort` 는 안정 정렬이
  아니라서 두 번 정렬하면 같은 날짜 안의 순서가 섞인다(실제로 섞였다). 파일명이
  `YYYY-MM-DD-NN-사람` 이라 경로를 뒤집으면 그대로 원하는 순서가 된다.

## 이관 (2026-08-27)

옛 항목 66건을 `_logs/` 로 옮겼다. **본문은 한 글자도 고치지 않았다**(절대 원칙 8).
불릿 193개가 이관 전후로 정확히 일치하는 것을 확인했다.

**작성자는 git 이력에서 찾았다.** `git blame` 은 쓸 수 없었다 — 번호 재정렬 머지가
한 사람 이름으로 24건을 통째로 덮어썼다. 대신 각 항목의 첫 불릿 텍스트로
`git log -S --reverse` 를 돌려 **그 문장을 처음 커밋한 사람**을 찾았다.

| | 건수 |
|---|---|
| 조서희 | 29 |
| 류준 | 19 |
| 정성윤 | 14 |
| 장민석 | 4 |

2건은 이 방법으로도 안 잡혀 본문 근거로 직접 지정했다 — `(29)`(프론트 대시보드 작업이라
조서희), `(8)`("내 이전 푸시 지점"·`STATE.md` 세션(이어서 5) 기록이라 류준).
**추정이 아니라 근거가 있는 배정이지만, 원래 항목에 작성자 필드가 없었으므로
100% 확정은 아니다.** 틀린 것이 있으면 해당 파일의 `author`/`person` 만 고치면 된다.

## 되돌리는 법

`_logs/*.md` 의 본문을 날짜·seq 역순으로 이어 붙여 `progress.markdown` 하나로 되돌리고,
`_config.yml` 의 `logs:` 컬렉션과 `scripts/check_session_end.py`·`check_progress_log.py` 의
경로를 원래대로 돌린다. **되돌리면 충돌도 함께 돌아온다.**
