이 사이트는 개발 제안서 형식이면서, 동시에 프로젝트의 현재 상태 그 자체다.
표지 → [목차]({{ '/toc/' | relative_url }}) → 5개 절이 제안서 본문이고, 그 아래 네 종류의 기록이 서로 다른 역할을 한다.

| | 무엇 | 시간 축 | 수정 |
|---|---|---|---|
| [개발 로그]({{ '/log/' | relative_url }}) (`_posts`) | 그날 무엇을 왜 했는가 | 과거 · 쌓기만 함 | 안 함 |
| [제안서 각 절]({{ '/toc/' | relative_url }}) (`_docs`) | 지금 무엇이 맞는가 | 현재 | 계속 덮어씀 |
| [진행 상황]({{ '/progress/' | relative_url }}) (`_data`) | 어디까지 왔고 숫자는 얼마인가 | 현재 | 계속 갱신 |
| [미결 항목]({{ '/open-items/' | relative_url }}) (`_data`) | 아직 정하지 못한 것 | 현재 | 해소 시 닫음 |

## 진행 로그의 형식

모든 로그는 네 절을 같은 순서로 갖는다.

```
## 한 일
## 판단과 근거      ← 버린 선택지도 함께
## 막힌 것
## 다음 세션 첫 작업
```

제목은 `W{주차} — {한 일}`. 이렇게 하면 8주 타임라인이 로그만으로 복원된다.

## 숫자를 믿어도 되는 이유

모든 성능 수치는 `_data/metrics.yml` 한 곳에서 온다. 각 값에는 측정일 · 커밋 해시 · 재현 명령 · 표본 수가 붙어 있다.
넷이 다 없는 값은 사이트에 나오지 않는다. 아직 측정하지 않은 항목은 **미측정**으로 표시된다.

## 실패도 남는다

미달한 지표, 안 된 실험, 틀린 가설은 지우지 않는다. 8주차 "실패 사례 분석" 의 재료다.
잘 된 것만 남은 기록은 기록이 아니다.

## 비공개 영역

기획서 원본, 세션 인수인계 상태(`STATE.md`), 결정 기록은 저장소의 `_project/` 에 있으며 사이트에는 공개되지 않는다.
약관 원문, 자격증명, 개인정보가 포함된 데이터 샘플도 공개하지 않는다.
